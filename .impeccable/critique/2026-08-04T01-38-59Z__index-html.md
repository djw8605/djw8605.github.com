## Design Specificity Verdict

**Split verdict: the chrome is authored for this person; the content architecture is a developer-portfolio template that has been filled in wrongly.**

**Genuinely product-specific** — the `//` mono eyebrow (a code comment used to label a page region, shown to people who read code comments all day); the PEARC 2025 hero plate with its bordered mono caption bar; the inverted hero grid (`0.76fr / 1.24fr`) that makes the photograph the *smaller* half, framing it as dated evidence rather than a portrait; NSF award numbers as first-class linked content; the terminal-style archive tag chip that deliberately refuses the pill shape everything else uses.

**Category-default** — the 8-card project grid with truncated summaries and a two-button footer; the blog cards; the "Featured posts" sidebar that is actually `site.posts limit:4` duplicating four of the six cards beside it; the two ambient blurred orbs, the one purely decorative gesture in a system that otherwise argues for every mark.

**The damning one:** the Technologies section is not merely category-default, it is imported from the wrong category and its data is wrong. See P0-1.

**Deterministic scan.** Detector run twice. Source markup (`index.html`, `_layouts`, `_includes`, `_pages`, `about.md`, `publications.md`, `_projects`): exit 2, **46 findings** — `design-system-font-size` 32, `gray-on-color` 12, `border-accent-on-rounded` 1, `overused-font` 1. Built `_site/`: exit 2, **2543 raw findings across 50 unique (rule, snippet) pairs** — the 55× multiplier is template repetition across 205 pages, not distinct defects.

**After triage, roughly 28 of the 46 source findings are actionable**, dominated by type-ramp drift.

Confirmed false positives:
- **`gray-on-color` ×12** — the class list contains `hover:bg-sky-500/10`, a 10% tint. The detector strips the opacity modifier. Measured in-browser: those icon links have transparent backgrounds. A further 13 hits come from scanning the compiled utility stylesheet, where every generated class coexists.

## Overall Impression

This is a handsome, disciplined, genuinely well-built visual system wrapped around a record that is not being maintained — which is the precise inversion of the product's stated goal. PRODUCT.md says success is "an authoritative professional record" and names staleness as the primary failure mode. The site currently reads as *"handsome site, unmaintained record."*

The single biggest opportunity is not visual. It is that **the design system is documented in detail and the content is not documented at all.** The `//` eyebrow has a named rule; the citation format does not. Mono has an invariant; project role attribution does not — which is exactly why the FabAID page ends with a sentence about the OSG executive team.

## What's Working

1. **The `//` mono eyebrow is a real signature, correctly scoped.** It works because IBM Plex Mono is *reserved* — it never sets a heading and never runs prose, so by the time it appears the reader has been trained that it means "annotation, not content." Most sites that mix mono in dilute it until it means nothing. This one didn't.

2. **Ring-first, flat-at-rest depth is disciplined and it earns something.** Rest shadows are capped at 3px/8%; depth appears only on interaction. This works not because flat is fashionable but because an infrastructure engineer's credibility comes from precision, and a page where nothing floats or glows unless you touch it *reads* as precise. The restraint is doing argumentative work.

3. **The hand-tuned dark mode actually succeeds — and it is the light theme that fails.** Measured: **zero contrast failures in dark mode across all 7 routes at both widths**, worst ratio 7.10:1, most overrides clearing 9–18:1. The `!important` block in `main.scss` that looks like a hack is the most rigorous accessibility work on the site. Light mode is where the failures are.

## Priority Issues

### [P0] The `// expertise → Technologies` section misrepresents the record

**What:** `index.html:115-121` aggregates `project.technologies` across all 8 projects into a 25-badge wall headed `Technologies`. The set includes **React, Next.js, Astro, Tailwind CSS, CSS3, HTML5, Vercel, Node.js, and GitHub Copilot**, and excludes **XRootD, HTCondor, CVMFS, OSDF, Ceph, Prometheus, and Grafana entirely** — the systems named in his own publication titles. `_projects/scitokens.md` declares three technologies and one is GitHub Copilot. `_projects/fabaid.md`, a national data-services fabric, lists `react, nodejs, nextjs, tailwindcss, css3, html5`. These were evidently harvested from each project's *marketing website* build stack.

**Why it matters:** This is the most prominent claim on the highest-traffic page and it is false in the direction that costs most. A PI sizing him up for a proposal, or a promotion committee, reads a list that says "web developer." It is the specificity test failing at its sharpest: swap in a random front-end developer's content and this section becomes *more* accurate, not less. It directly violates PRODUCT.md Principles 1 and 2.

**Fix:** Rewrite `_data/technologies.yml` and every project's `technologies:` list around the actual engineering substrate — XRootD, HTCondor, CVMFS, OSDF, Kubernetes, Go, Python, OpenSearch, Ceph, Helm, SciTokens/JWT. Delete every web-framework and Copilot entry. Then either group the home badges into ≤6 per category (Data & Storage / Compute & Orchestration / Observability / Security) or cut the home section entirely and keep badges on project pages where they have context.

**Suggested command:** `/impeccable clarify`

### [P0] `publications.md` fails the exact audience it exists for

**What:** ~40 citations in one flat bulleted list. Concretely: **"Data Access for LIGO on the OSG" is listed twice** (lines 42 and 46) in two different formats; **five CHEP18 entries are still marked `(Accepted)`** (lines 35-39) eight years on; four entries end in the bare word `Online` with **no link at all** (lines 48-51); reverse-chronological order breaks at lines 52-53; three citation styles coexist; the `## Awards` section's single entry duplicates a publication already listed; and the heading reads **`## Presentatations`** with `sceintific` in the talk below it. Assessment B adds: of 41 markdown links, **17 use generic text** (`Online` ×6, `slides` ×5, `online` ×3, `poster` ×1) and **18 more use a bare DOI URL as visible link text**.

**Why it matters:** A tenure reviewer or program officer opens exactly this page and does exactly one thing: verify. A duplicate entry and five stale "Accepted" markers are not cosmetic — they are the reader's evidence that the record is not maintained, which contaminates everything else on the site. Two typos in a five-line section compound it.

**Fix:** *Immediately* — de-duplicate LIGO, resolve the five CHEP18 papers to published DOIs, replace bare `Online` with real links, fix both typos, restore strict reverse-chron. *Structurally* — move to `_data/publications.yml` with `year / venue / type / doi / authors` fields, render grouped by year with a venue filter and per-entry anchors, add BibTeX export, and link ORCID + Google Scholar at the top. Data-driven also makes "add a publication" a two-line YAML edit, which protects PRODUCT.md Principle 5.

**Suggested command:** `/impeccable shape` (this needs an information-architecture rethink, not a copy pass)

### [P0] Measured WCAG AA failures, on a site where AA is a binding constraint

PRODUCT.md records WCAG 2.1 AA as non-negotiable. DESIGN.md claims the floor "must be held, not regressed." Measurement says the floor was never reached. All figures below are computed, not estimated.

**Contrast — light mode only (dark mode passes cleanly):**
- **Prose links: 2.65:1, needs 4.5:1.** `[&_a]:text-sky-500` (`#0ea5e9`) on `#f8fafc`, from `single.html:33` and `project.html:29`. Hits **every blog post, `/about/`, `/publications/`, and every project page.** Also fails as large text — a linked 30.4px heading measures 2.65:1 against a 3.0:1 requirement. For reference `sky-600` = 3.91:1 (still fails); `sky-700` = 5.67:1 (passes).
- **Eyebrow labels: 2.45:1.** `text-slate-400` at 12px, at `index.html` lines 17, 63, 96, 117, 128 — including the site's signature `// research infrastructure`. `slate-500` = 4.55:1 is the marginal pass.
- **Focus ring: 2.30:1, fails SC 1.4.11 (3:1).** The global `rgba(14,165,233,.85)` outline. Icon links are worse at **1.85:1** — the weakest indicator on the site. Dark mode passes at 5.37:1.

**Structure:**
- **No `<main>` landmark and no skip link, across all 205 pages.** WCAG 2.4.1 (Level A). On `/year-archive/` a keyboard user traverses 40+ links to reach content.
- **41 links with no accessible name on `/year-archive/`** — the empty teaser-slot fallback in `archive-single.html` renders `<a>` with no text, no image, no `aria-label`. WCAG 2.4.4 / 4.1.2 (Level A).
- **No `aria-expanded` on the hamburger** — reads `null` both open and closed. Site-wide aria counts: `aria-hidden` 39, `aria-label` 13, `aria-pressed` 3, `aria-expanded` **0**.
- **No `prefers-reduced-motion` block anywhere**, against global smooth scroll plus hover transforms.
- **97 of 147 content `<img>` tags lack `alt`** (66%), all in Blogger-era posts. Templates are clean — every template image has alt.

**Fix:** Darken prose links to `sky-700` in light mode; move eyebrows to `slate-500` minimum; strengthen the focus ring. Add a visually-hidden-until-focused skip link as the first child of `<body>` and wrap `{{ content }}` in `<main id="main-content">`. Give the no-teaser `<a>` an `aria-label`, or make it a non-interactive `<div>`. Wire `aria-expanded` into the menu toggle. Add a `@media (prefers-reduced-motion: reduce)` block.

**Suggested command:** `/impeccable audit`

### [P1] The archive is 82% unrenovated Blogger HTML, and it undermines the depth it should demonstrate

**What:** 94 of 114 posts are `.html` Blogger imports. **136 plain-`http://` image sources across 62 posts** — Assessment B probed the hosts: `3.bp.blogspot.com` responds over HTTPS so Chrome's auto-upgrade rescues ~118 of them, but **`www-hep.nhn.ou.edu` and `gratiaweb.grid.iu.edu` do not respond over HTTPS at all**, so those 4 are permanently broken in production. **94 posts link outward to `derekweitzel.blogspot.com`** rather than to their own migrated siblings. 34 reference the defunct `twiki.grid.iu.edu`. 4 embed Flash `<object>` that renders as blank space. Body text is `<br />`-joined blobs. No post has an `excerpt:` or a `category`.

Separately, the tag taxonomy is not fit for purpose: 26 tags over 114 posts, `osg` covers 70 of them (a facet selecting 61% of the corpus is not a facet), casing is inconsistent (`osg`, `CERN`, `Visualization`, `X`), and **`xrootd`, `kubernetes`, `scitokens`, `osdf`, and `stashcache` are not tags at all** — the exact search-arrival topics PRODUCT.md names as the engineer audience's entry vectors.

**Correction to one claim:** the design review reported "a wall of broken-image icons" down `/year-archive/`. Measurement contradicts this — **0 broken images across all 28 audits**. The real defect is different and it is the accessibility one above: 41 posts fall through to the empty teaser branch and render as **blank gray boxes that are also unlabeled links**.

**Why it matters:** PRODUCT.md Principle 4 says the archive is an asset only if it stays legible, and the search-arriving engineer — one of four co-primary audiences — lands *directly* on these pages. Note also that the archive's center of mass is 2011–2013 (68 of 114 posts), while 2019–2026 contributed 7 posts total and 2021/2023/2025 are empty.

**Fix:** Script-rewrite `http://` → `https://` where hosts resolve, and remove the `<img>` where they don't. Rewrite blogspot links to local equivalents. Strip the Flash embeds. Add an auto-rendered context note in `single.html` for posts older than ~5 years. In `post-image-url.html`, reject scraped `http://` URLs. Add HTML-proofer to CI. Add `xrootd`/`kubernetes`/`scitokens`/`osdf` to the taxonomy and normalize casing.

**Suggested command:** `/impeccable harden`

### [P1] The 404 promises a search that does not exist, and neither does site search

**What:** `_pages/404.md` reads *"perhaps you can try searching for it below"* and then loads `//linkhelp.clients.google.com/tbproxy/lh/wm/fixurl.js` — Google's retired Webmaster Tools widget. Nothing renders. No links onward. The excerpt reads *"Your pixels are in another canvas."* Separately, there is no search on any surface across 114 posts and 17 years.

**Why it matters:** PRODUCT.md states inbound traffic is substantially search-driven onto single deep pages, across 17 years of migrated permalinks. The 404 is a load-bearing surface, and it is both non-functional and actively lying. The "pixels" line is also flatly off-voice for a system whose register is "precise, quiet, technical."

**Fix:** Delete the dead script, rewrite the copy in-voice, add real recovery links. Add client-side search — a build-time `search.json` of title + tags + excerpt with a small vanilla-JS filter is fully compatible with static GitHub Pages and would serve the archive, the 404, and the reviewer at once.

**Suggested command:** `/impeccable clarify`

## Questions to Consider

1. **If the technologies list had to be defensible in a proposal narrative, would a single one of `react`, `nextjs`, `astrojs`, `tailwindcss`, `vercel`, `css3`, `html5`, or `githubcopilot` survive?** And if the honest list is XRootD, HTCondor, CVMFS, OSDF, and OpenSearch — none of which have a marketable logo — is the badge component itself simply the wrong form for this record?

2. **The stated success criterion is accuracy and the stated failure mode is staleness, so why is there no mechanism that resists either?** Would one afternoon on `_data/publications.yml` plus an HTML-proofer CI step protect the product more than every remaining item in this critique combined?

3. **94 of 114 posts link outward to a defunct Blogger blog, 62 carry mixed-content images, and there is no search.** Is the archive currently an asset, or a liability that a visitor's first click into 2011 converts into evidence of neglect? What would it cost to keep the 30 posts still worth reading and formally retire the rest, versus renovating all 114?

4. **The home page presents Hero, Projects, Technologies, and Blog as four co-equal sections under identical hairlines** — but the four audiences want four different things, and the engineer never sees the home page at all. If it had to route three distinct verification jobs in under ten seconds, is a stack of equal-weight sections the right composition, or does it need three explicit named doors?

5. **The design system is documented in 22 KB of DESIGN.md and the content is not documented at all.** Should the next unit of work be a rendered pixel, or a content schema?
